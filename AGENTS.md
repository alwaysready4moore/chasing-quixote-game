# Chasing Quixote — Agent Working Rules

## Working model
The creator's preference is **you build, I enhance**. Make reasonable implementation choices, complete coherent work units, and open PRs for review rather than interrupting for routine approvals. Do not overwrite approved creative content or invent canon.

## Boundaries
1. Ren'Py is the target engine. HTML files are historical prototypes, not the production source.
2. GitHub contains code, non-spoiler specs and approved release-safe assets. The authoritative manuscript, spoiler ledger and draft art are maintained in the linked private production materials. Do not reproduce private content in this public repository without approval.
3. The player controls approaches and discovery, never Fox's underlying personality or the canonical murderer/ending.
4. Never convert neurological symptoms, mobility, fatigue, addiction recovery or mental-health care into punishment meters, random failure, or competence debuffs.
5. Keep all gameplay input accessible: keyboard navigation, readable contrast, persistent clue review, text alternatives for audio, and no mandatory timed reflex input.
6. Never add courtroom gameplay, statement-by-statement Press/Present or credibility points. Build scene reconstruction through linked observations, conversations, and contextual hypotheses.
7. Treat placeholder writing explicitly as non-canon; verify dialogue changes against the manuscript and characterization materials before marking them final.
8. Separate narrative content from interaction logic. Prefer small labels, screens and shared data rather than enormous scripts.
9. Validate save/load, rollback, and every branching route. Do not claim Ren'Py has been tested until it has been run and errors checked.

## Development process
- Inspect existing code and issues first.
- Work in focused branches. Include a short test checklist in each pull request.
- Keep replacement artwork behind stable asset IDs; maintain consistent backgrounds, sprite anchors, and expression framing.
- Store asset sources, attribution/provenance and licenses before release.
- Never commit tokens, private document exports or unpublished twist summaries.
